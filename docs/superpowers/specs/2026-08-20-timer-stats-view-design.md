# 타이머 화면 "통계" 모드 설계

**날짜:** 2026-08-20
**상태:** 승인됨
**상위 문서:** `docs/superpowers/specs/2026-08-20-timer-redesign-design.md`, Claude Design 목업 `English Helper UI.dc.html` §1e (2026-08-20 갱신본 — 통계 모드 추가)

---

## 1. 배경

1e 재설계(§2026-08-20 스펙)를 이미 구현·병합 대기 중인 상태에서 목업이 갱신되어, 타이머 화면 우측 상단에 달력 아이콘 토글 버튼이 추가되고 이를 누르면 "통계" 모드(기간 선택 + 요약 + 달력 히트맵 + 일별 상세 + 연속 학습 + 목표 달성률)로 전환되는 기능이 새로 생겼다. 또한 이번 작업과 별개로, 앱의 하단 네비게이션 탭 순서가 목업(`AppNav.dc.html`: 홈/플래시카드/타이머/가져오기/설정)과 어긋나 있던 버그를 발견해 별도로 수정했다(`mobile/lib/app.dart`, 이미 커밋됨 — 이 스펙의 범위 밖).

## 2. 범위

- **포함:** 타이머 화면에 "타이머"/"통계" 두 모드 토글(우상단 아이콘 버튼), 통계 모드의 기간 선택기(주/월/년), 요약 카드(총 학습시간+평균+막대그래프), 월별 달력 히트맵(일별 학습량에 따라 점 크기 3단계), 탭한 날짜의 상세(학습 시간/세션 수/저장 개수), 연속 학습일수(현재+최장), 목표 달성률(이번 달 활동일 비율).
- **제외:** 새 패키지 의존성 추가(달력 그리드는 순수 `DateTime` 계산으로 직접 구현), 주간 목표 이력 기반의 "주 단위 달성률"(§4에서 정의를 재해석해 일 단위 활동률로 단순화 — 이유는 §4 참고).

## 3. 화면 구조

### 3.1 모드 토글

`timer_screen.dart`에 `bool _statsMode` 상태를 추가한다. 헤더 우측에 아이콘 버튼(달력 아이콘 ↔ X 아이콘)을 두고 탭하면 토글한다. `_statsMode == false`일 때는 기존 "타이머" 모드(현재 이미 구현된 타이머 카드+주간목표+최근세션+히스토리뷰) 그대로. `_statsMode == true`일 때 아래 §3.2~§3.6의 통계 모드를 보여준다.

### 3.2 기간 선택기

주/월/년 3분할 세그먼트(기존 `TimerHistoryView`의 `TimerPeriod` enum·`_rangeFor` 로직과 동일한 개념을 재사용 — 단, `TimerHistoryView`는 건드리지 않고 통계 모드 전용으로 별도 구현한다. `TimerHistoryView`는 여전히 "타이머" 모드에만 존재하는 별개 위젯이다).

### 3.3 요약 카드

- 좌측: 기간 라벨("이번 주"/"이번 달"/"올해" 등) + 해당 기간 총 학습시간(H:MM).
- 우측: "평균" 라벨 + 기간 내 활동일당 평균 학습시간(H:MM). 활동일이 0이면 평균은 "0:00"으로 표시(0으로 나누기 방지).
- 하단 7칸 막대그래프: 주 기간이면 요일별(월~일), 월 기간이면 주차별(1~5주차), 년 기간이면 월별(1~12월 중 최근 7개월 또는 균등 샘플링 — 이번 구현에서는 최근 12개월을 7칸이 아니라 그대로 12칸으로 그린다. 목업의 "7칸" 고정은 주간 뷰 기준 예시이고, 월/년 뷰는 자연스러운 칸 수(월=주차 수, 년=12개월)를 쓴다. 막대 색상은 기존 주간 목표 카드와 동일한 규칙(오늘/이번 구간=액센트, 그 외 활동 있음=피치 틴트, 활동 없음=연회색)을 재사용).
- 하단 한 줄: 전 기간 대비 변화("{증감}분 {증가/감소}" 형태)는 이번 구현에서 생략하고 대신 "지난 기간과 비교"를 계산하지 않는 대신 고정 안내 문구("최근 {N}개 구간 기준")로 대체한다 — 전 기간 대비 델타 계산은 범위 밖으로 명시(§ 6).

### 3.4 달력 히트맵

- 월 단위 그리드(월요일 시작, 7열). 이전/다음 달 이동 버튼.
- 각 날짜 셀: 날짜 숫자 + 그날 학습 시간에 비례한 점(dot). 점 크기 3단계:
  - 0분: 점 없음(빈 칸).
  - 그 달 최대 일일 학습시간의 33% 미만: 작은 점.
  - 33~66%: 중간 점.
  - 66% 초과: 큰 점.
  (월 전체에서 학습 기록이 하나도 없으면 모든 날짜가 점 없음.)
- 오늘 날짜 셀은 텍스트 굵게 표시.
- 셀을 탭하면 §3.5의 일별 상세가 그 날짜로 갱신된다(기본값: 오늘).

### 3.5 일별 상세

탭(또는 기본 선택된) 날짜의: 학습 시간(H:MM), 세션 수(그날 종료된 `StudySession` 개수), 저장 개수(그날 저장된 `Word`+`Sentence` 총합 — `savedAt` 문자열의 날짜 부분이 일치하는 항목 수. `LearningRepository.getWords()`/`getSentences()`는 날짜 필터를 지원하지 않으므로 전체를 가져와 클라이언트에서 날짜별로 그룹화한다).

### 3.6 연속 학습 · 목표 달성률

- **연속 학습**: 오늘부터 거슬러 올라가며 하루라도 학습 세션이 있었던 날이 며칠 연속인지(현재 스트릭). 최장 스트릭은 전체 세션 이력에서 계산한 가장 긴 연속 활동일 구간.
- **목표 달성률(재정의)**: 목업 예시 문구("이번 달 18/28일")를 그대로 따라, **주간 목표 이력이 아니라 "이번 달 중 하루라도 학습한 날 수 ÷ 이번 달 경과일 수"**로 정의한다. 원래 "주간 목표 달성 주 수 비율"로 읽힐 수도 있으나, 그러려면 매 주마다 `getWeeklyGoalMinutes`를 개별 조회해 과거 목표 이력을 복원해야 해서 훨씬 복잡해지고, 목업 예시 숫자(18/28)는 "일" 단위로 명시돼 있어 활동일 비율 해석과 정확히 맞는다. 이 해석을 채택한다.

## 4. 데이터 흐름

`TimerScreen`(또는 새 `_StatsView` 위젯)이 `context.watch<StudyTimerRepository>()`와 `context.watch<LearningRepository>()`를 모두 구독한다(§ 리서치에서 확인: 같은 `MultiProvider`에 등록되어 있어 문제없이 동시 접근 가능). 필요한 범위의 `getSessionsBetween`/`getWords`/`getSentences`를 호출해 클라이언트에서 집계한다. 리포지토리 인터페이스는 변경하지 않는다.

## 5. 에러 처리

- 선택 기간에 세션이 하나도 없으면 요약 카드의 총합/평균은 "0:00"으로, 막대그래프는 전부 빈 상태로 표시(에러 없이 0 값 정상 표시).
- 달력에서 학습 기록이 없는 달을 넘겨봐도 정상 렌더링(모든 셀 점 없음).
- 연속 학습이 0일(활동 없음)이면 "0일"로 표시.

## 6. 테스트

- 모드 토글: 아이콘 탭 시 타이머 모드 ↔ 통계 모드 전환, 아이콘 자체도 바뀌는지.
- 기간 선택기: 주/월/년 전환 시 요약 카드 라벨과 막대그래프 칸 수가 바뀌는지.
- 요약 카드: 총합/평균 H:MM 포맷, 활동일 0일일 때 평균이 "0:00"인지.
- 달력: 특정 달에 학습 기록이 있는 날은 점이 표시되고 없는 날은 점이 없는지, 점 크기 3단계 임계값 경계(정확히 33%/66%) 테스트.
- 일별 상세: 날짜 셀 탭 시 그 날짜의 학습시간/세션수/저장개수로 갱신되는지, 저장개수가 단어+문장 합산인지.
- 연속 학습: 연속된 날짜에 세션이 있을 때 정확한 일수 계산, 중간에 하루라도 비면 스트릭이 끊기는지, 최장 스트릭이 현재 스트릭보다 긴 과거 구간을 올바르게 찾는지.
- 목표 달성률: 이번 달 활동일 수 ÷ 경과일 수 계산이 정확한지(경계값: 월 첫날, 오늘이 월말인 경우).

## 7. 범위 밖 (재확인)

- 새 패키지 의존성(달력 UI 전용 패키지 등)
- 전 기간 대비 증감 델타 계산(`statDelta`)
- 주간 목표 이력 기반의 "몇 주 달성했는지" 집계
- `TimerHistoryView`(기존 타이머 모드의 주/월/년+그래프/숫자 위젯) 변경 — 완전히 별개로 남긴다
