# 영상 위 UI 재설계 (1h/1i) 설계

**날짜:** 2026-08-21
**상태:** 승인 대기
**상위 문서:** Claude Design 목업 `English Helper UI.dc.html` §1h/§1i, §1a (자막은 어둡게, 학습은 밝게)

---

## 1. 배경

Chrome 확장의 영상 위 UI(자막 오버레이·스크립트 패널·단어 팝업)는 Phase A 때 만들어진 뒤 목업과
크게 달라졌다. 특히 목업은 이제 페이지에 **상단 설정 바**(자막 오버레이/스크립트 패널 토글 +
설정 버튼)를 항상 띄워두고, 그 안에서 열리는 **설정 패널**에 모국어/표시모드/자막 크기(영어·모국어
각각 독립 조절)/미리보기/내보내기(스크립트 .srt·.txt, 저장 항목 .sqlite)를 전부 담는다. 이는
기존에 브라우저 툴바 팝업(1g)이 맡던 표시/설정 기능을 페이지 내부로 옮긴 것이다 — 1g는 이번
작업과 별개로 단어/문장 목록 + 내보내기만 남기고 축소한다(§2026-08-21-import-settings-design.md
와 무관한 별도 문서로, 팝업 쪽 별도 작업에서 다룬다).

## 2. 범위

- **포함:**
  - 상단 설정 바 신규 추가 (자막 오버레이/스크립트 패널 토글, 저장 개수, 설정 버튼)
  - 설정 패널 신규 추가 (모국어, 표시모드, 영어/모국어 자막 크기 독립 슬라이더, 미리보기,
    스크립트 내보내기, 저장 항목(.sqlite) 내보내기)
  - 자막 오버레이·단어 팝업 목업 스타일 정합(색상/타이포/카드 스타일)
  - 스크립트 패널: 검색·필터, 줄별 저장 상태 표시(이미 저장된 줄 구분), 자동 스크롤 토글 추가
  - 스크립트 내보내기 포맷을 현재 HTML 단일 포맷에서 목업이 요구하는 형태로 재검토(§5.2)
- **제외:** 새 스트리밍 플랫폼 어댑터 추가, 온보딩(1b) 화면, 단어 팝업 자체의 복습 스케줄링 로직
  변경(기존 `markWordReviewed` 등 그대로 사용)

## 3. 기존 동작과의 충돌 — 명시적 결정

기존 `core/subtitle-engine.js`는 자막 오버레이를 **드래그로 자유 배치**하고 **리사이즈 핸들로
크기 조절**할 수 있다(`attachDrag`/`attachResize`, `localStorage`에 위치 저장). 목업은 자막을
화면 하단 중앙에 **고정 위치**로 그린다(위치 조절 UI가 아예 없음).

**결정:** 드래그/리사이즈 기능은 목업에 없지만 기존 사용자 기능이므로 제거하지 않고 유지한다.
목업의 "하단 중앙"은 **기본 위치**로만 적용하고(현재 코드가 `restorePosition`에서 저장된 위치가
없을 때만 기본값을 쓰는 구조를 그대로 활용), 드래그로 옮긴 뒤에는 여전히 그 위치를 기억한다.
자막 크기는 기존처럼 리사이즈 핸들로도 바꿀 수 있고, 새 설정 패널의 슬라이더로도 바꿀 수 있다
(값은 `chrome.storage.local`의 `eh-settings`로 양쪽이 공유).

## 4. 상단 설정 바

`core/subtitle-engine.js`의 `createDOM()`이 만드는 기존 `#eh-overlay`(자막 두 줄 + 리사이즈
핸들)와 별개로, 새 `#eh-topbar` DOM을 페이지 상단에 고정 삽입한다(목업 46px 높이, 배경
`#15181d`, 하단 테두리 `rgba(255,217,122,.16)`).

- 좌측: "English Helper" + 플랫폼 배지(예: 목업의 `{{hostBadge}}` — 실제로는 현재 재생 중인
  플랫폼 이름, `adapter.getPlatformMeta().platform`에서 가져온다)
- 구분선 다음: 자막 오버레이 토글, 스크립트 패널 토글 — 각각 클릭 시 기존
  `SubtitleEngine.toggle()`/`ScriptPanel.toggle()`을 직접 호출(더 이상 팝업의
  `TOGGLE_OVERLAY`/`TOGGLE_PANEL` 메시지를 거칠 필요 없음 — 같은 페이지 안에서 직접 호출 가능.
  단, 팝업에서도 여전히 토글할 수 있어야 하므로 기존 메시지 리스너는 그대로 둔다)
- 우측: "저장 {count}" — **전체 누적** 저장 개수(`chrome.runtime.sendMessage({type:'GET_ALL'})`
  결과의 words+sentences 총합, 페이지 로드 시 1회 조회 후 저장 이벤트마다 갱신). 스크립트 패널
  하단의 "이 영상에서 저장 {n}"(§1i, 현재 영상에 한정된 개수)과는 다른, 별개의 지표다 — 혼동하지
  않도록 상단 바는 항상 전체 누적 개수만 표시한다.
- "설정" 버튼: 클릭 시 설정 패널 토글 표시

## 5. 설정 패널

바 아래 오른쪽에 고정 폭 308px 카드로 뜬다(배경 `rgba(21,24,29,.97)`, blur 없음 — content
script 안에서 backdrop-filter는 성능 이슈가 있을 수 있어 반투명 배경색만 사용).

### 5.1 항목

- **모국어**: 현재 팝업과 동일한 6개 언어 선택(칩 형태, 목업 그대로)
- **자막 표시 모드**: 영어만 / 영어+모국어 (기존 `mode` 설정과 동일한 값)
- **영어 자막 크기 / 모국어 자막 크기**: 각각 독립적인 틱 슬라이더(목업의 `enTicks`/`koTicks`
  패턴 — 12개 눈금이 아니라 9개 눈금, 값 목록은 구현 시 `[12,16,20,24,28,32,38,44,52]`처럼 현재
  `enSize`(12~52) 범위를 9단계로 나눠 사용). **1g 팝업에서 검토했던 "모국어=영어×72% 자동 계산"
  방식은 채택하지 않는다** — 여기서는 두 값 모두 독립적으로 저장된 `enSize`/`nativeSize`를 그대로
  쓴다(기존 `DEFAULT_SETTINGS`/`saveSettings` 구조 그대로 재사용, 팝업과 저장 패널이 있다면 팝업
  것도 동일한 값 공유).
- **미리보기**: 검은 배경 카드에 현재 크기로 예문 렌더링(목업 그대로, `dual` 모드일 때만 모국어
  줄 표시)
- **내보내기**:
  - "스크립트 내보내기" — 현재 영상의 자막 줄들을 내보낸다. **포맷 결정**: 현재 구현은 HTML
    단일 포맷이다(`_buildExportHtml`, Script HTML Export 기능으로 이미 완성·리뷰됨). 목업은
    `.srt / .txt`라고 표시하지만, 이는 이번 재설계의 핵심이 아니고 기존에 이미 검증된 HTML
    export를 대체할 만한 이유가 없다 — **버튼 라벨의 확장자 표시만 없애고 기존 HTML export를
    그대로 연결한다** (`ScriptPanel.exportScript()` 재사용). 별도 .srt/.txt 포맷 추가는 범위
    밖으로 명시한다.
  - "저장 항목 내보내기" — 기존 팝업의 SQLite export 로직(`initSqlJs`, words/sentences 테이블
    빌드)을 그대로 재사용. 이 로직은 현재 `popup/popup.js`에만 있으므로, `core/` 아래 공유
    가능한 모듈(`core/sqlite-export.js`)로 추출해 팝업과 설정 패널 양쪽에서 `import`(스크립트
    태그로 로드, 모듈 시스템 없음 — 기존 코드 관례대로 `window.EH.*` 네임스페이스에 등록)한다.

### 5.2 데이터 흐름

설정 패널의 모든 컨트롤은 기존 `window.EH.applySettings(patch)` (in `adapter-interface.js`)를
그대로 호출한다 — 새 메시지 타입이나 별도 저장 경로를 만들지 않는다. 언어/모드/두 크기 값 모두
이미 `DEFAULT_SETTINGS`에 있거나(추가 필요한 것: 없음 — `enSize`/`nativeSize`/`mode`/`nativeLang`
전부 이미 존재) 그대로 쓸 수 있다.

## 6. 스크립트 패널 확장

기존 `core/script-panel.js`(363줄, `renderList`/`highlight`/`toggle`/`applySettings` 보유)에
다음을 추가한다:

- **검색**: 입력 상자, 영어/모국어 텍스트 부분 일치로 줄 필터링(클라이언트 사이드, 정규식 이스케이프
  필요 — 특수문자 포함 검색어로 인한 오류 방지)
- **줄별 저장 상태**: 이미 저장된 문장은 "＋" 대신 체크 표시 — 현재 세션의 저장된 문장 id 목록을
  자막 원문과 매칭(정확한 매칭 방법은 계획 단계에서 확정 — 문장 자체 텍스트 비교가 가장 단순함)
- **자동 스크롤**: 토글 버튼, 현재 재생 위치에 해당하는 줄로 자동 스크롤(이미 `highlight(enText)`가
  현재 줄을 하이라이트하고 있으므로, 그 줄이 뷰포트 밖이면 `scrollIntoView` 호출만 추가하면 됨)

## 7. 스타일 정합

`ui/tokens.css`(다크 서페이스 토큰, 이미 존재)를 상단 바/설정 패널/자막/단어 팝업/스크립트 패널
전체에 적용한다. 현재 `ui/overlay.css`(254줄)가 이미 이 파일들의 스타일을 담당하고 있으므로,
새 클래스만 추가하고 색상 리터럴은 전부 `var(--eh-*)` 토큰으로 교체한다(하드코딩된 hex가 있다면
정리 — 기존에도 일부 있을 수 있음, 구현 시 확인).

## 8. 에러 처리

- 설정 패널이 열려 있는데 페이지 이동/영상 전환이 일어나면 패널은 유지하되 미리보기 예문은
  현재 재생 중인 자막이 없으면 목업의 정적 예문("I don't even care anymore.")으로 폴백한다
  (이미 팝업에도 동일 폴백 존재).
- 검색어가 스크립트 어떤 줄에도 매치하지 않으면 "검색 결과가 없습니다" 빈 상태 표시.
- SQLite export가 실패하면(팝업과 동일하게) 버튼 텍스트를 "내보내기 실패"로 잠깐 표시 후 복구.

## 9. 테스트

Chrome 확장 콘텐츠 스크립트는 현재 프로젝트에 자동 테스트 하네스가 없다(Flutter 쪽만 `flutter
test`가 있음). 기존 관례대로 수동 검증 체크리스트로 대체한다:
1. 지원 플랫폼(YouTube/Netflix/Disney+/쿠팡플레이) 영상에서 상단 바가 뜨는지, 토글 2개가
   실제 오버레이/패널을 켜고 끄는지
2. 설정 버튼 클릭 시 패널이 열리고, 모국어/모드/크기 슬라이더 2개가 즉시 자막에 반영되는지
3. 자막 단어 클릭 시 팝업이 뜨고 단어/문장 저장이 동작하는지(기존 기능 회귀 없는지)
4. 스크립트 패널에서 검색어 입력 시 줄이 필터링되는지, 이미 저장한 줄에 체크 표시가 뜨는지,
   자동 스크롤 토글이 현재 줄로 스크롤하는지
5. 설정 패널의 "스크립트 내보내기"/"저장 항목 내보내기" 버튼이 각각 정상 다운로드되는지
6. 기존 드래그/리사이즈가 여전히 동작하는지(§3 결정사항 회귀 확인)

## 10. 범위 밖 (재확인)

- .srt/.txt 스크립트 export 포맷 추가(기존 HTML export 유지)
- 1g 팝업의 표시/설정 탭 제거 작업 자체(별도 문서/작업으로 진행)
- 온보딩(1b), 새 어댑터, 복습 스케줄링 로직 변경
